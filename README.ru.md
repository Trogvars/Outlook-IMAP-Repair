# Outlook IMAP Repair

**Исправление ошибки Outlook 0x80040605 в существующих IMAP-профилях без пересоздания учётных записей и файлов OST.**

**Языки:** [English](README.md) | Русский

> **Статус:** пилотный инструмент администратора. Точечное исправление проверено на Outlook LTSC 2021 x64. Массовый режим и автоматическое развёртывание на RDS требуют дополнительного тестирования. Скрипты теперь находятся в репозитории. Перед массовым применением проверь их в своей среде.

## Описание проблемы

В некоторых старых IMAP-профилях **классического Microsoft Outlook** при переходе в **Файл → Настройка учётных записей → Настройка учётных записей → Файлы данных → Параметры** возникает **0x80040605**. Такая же ошибка может появляться при конфигурировании службы через [MFCMAPI](https://github.com/microsoft/mfcmapi).

При этом получение и отправка писем могут работать, но свойства OST и кнопка ручного сжатия оказываются недоступны. Проверка SCANPST и восстановление Office не обязательно помогают. Новый профиль Outlook работает, однако на терминальном сервере пересоздавать множество IMAP-учётных записей неудобно.

Проблема в исследованных случаях была связана с конфигурацией службы **INTERSTOR** в MAPI-профиле. Какое именно обновление Office привело к такому состоянию, **пока не установлено**.

## Найденное исправление

При успешном исправлении одновременно изменялись **два свойства**:

| Свойство MAPI | Было | Стало |
| --- | --- | --- |
| **PR_SERVICE_ENTRY_NAME_A** — 0x3D0B001E, PT_STRING8 | PRXServiceEntry@40 | PRXServiceEntry |
| **PR_SERVICE_SUPPORT_FILES_A** — 0x3D0F101E, PT_MV_STRING8 | Отсутствует | ANSI-массив с одним элементом: pstprx.dll |

Отсутствующее свойство в MFCMAPI может отображаться так:

~~~text
Property: PR_SERVICE_SUPPORT_FILES
Tag:      0x3D0F000A
Type:     PT_ERROR
Error:    0x8004010F (MAPI_E_NOT_FOUND)
~~~

**Важно:** PT_ERROR / MAPI_E_NOT_FOUND — **результат чтения отсутствующего свойства**, а не реально сохранённое свойство с ошибочным типом. Нужно создать **PR_SERVICE_SUPPORT_FILES_A** с типом **PT_MV_STRING8**, содержащим ANSI-строку pstprx.dll.

Оба параметра менялись одновременно. Это **не доказывает**, что каждое из этих изменений по отдельности необходимо или достаточно.

## Требования

- Windows и **классический Outlook LTSC 2021 x64**, почтовые учётные записи IMAP (проверенная конфигурация).
- **Windows PowerShell 5.1 x64**, редакция Desktop. Не использовать PowerShell 7 или 32-битный PowerShell.
- Запускать **в сеансе соответствующего пользователя Windows**, не от SYSTEM и не от имени другого администратора.
- Перед исправлением закрыть Outlook и MFCMAPI.
- Visual Studio и дополнительные модули PowerShell на сервере не нужны: используются Add-Type и Extended MAPI установленного Outlook.

Другие версии Office, Exchange/POP3 и иные архитектуры **не проверены**.

Проверка среды:

~~~powershell
[PSCustomObject]@{
    Version = $PSVersionTable.PSVersion.ToString()
    Edition = $PSVersionTable.PSEdition
    Is64Bit = [Environment]::Is64BitProcess
    Path    = (Get-Process -Id $PID).Path
}
~~~

Обычный путь к 64-битному Windows PowerShell:

~~~text
C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
~~~

При запуске **из 32-битного процесса** для обращения к 64-битному PowerShell может потребоваться псевдокаталог **Sysnative**.

## Использование

Основной скрипт — [Repair-OutlookIMAP-v2.ps1](Repair-OutlookIMAP-v2.ps1). Команды выполняются из каталога со скачанным файлом.

### Диагностика без изменений

~~~powershell
.\Repair-OutlookIMAP-v2.ps1
.\Repair-OutlookIMAP-v2.ps1 -Profile "Outlook"
~~~

Статусы:

| Статус | Значение |
| --- | --- |
| **OK** | Оба исправленных свойства уже присутствуют |
| **CANDIDATE** | Обнаружена точная комбинация двух проблемных значений |
| **SKIP** | Другая конфигурация; не изменяется |
| **ERROR** | Ошибка чтения или обращения к MAPI |
| **FIXED** | Значения записаны, сохранены и проверены повторным чтением |

### Исправление одного IMAP-ящика

Укажи **реальный UID из 32 шестнадцатеричных символов**, полученный при диагностике:

~~~powershell
.\Repair-OutlookIMAP-v2.ps1 -Apply -Profile "Outlook" -Uid "0123456789ABCDEF0123456789ABCDEF"
~~~

### Исправление всех проблемных служб одного профиля

~~~powershell
.\Repair-OutlookIMAP-v2.ps1 -Apply -Profile "Outlook" -All
~~~

Изменяются **только** службы, у которых совпали оба исходных признака. Остальные MAPI-службы не затрагиваются.

### Терминальный сервер / RDS

Дополнительная обёртка [Invoke-RDS-OutlookRepair.ps1](Invoke-RDS-OutlookRepair.ps1) запускает основной скрипт для выбранных профилей **текущего пользователя**:

~~~powershell
# Проверить профиль Outlook по умолчанию
.\Invoke-RDS-OutlookRepair.ps1

# Исправить профиль по умолчанию
.\Invoke-RDS-OutlookRepair.ps1 -Apply

# Исправить все профили пользователя, включая тестовые копии
.\Invoke-RDS-OutlookRepair.ps1 -Apply -AllProfiles
~~~

Для всех пользователей RDS можно организовать запуск **в пользовательском контексте** при входе в систему, например через пользовательский logon-скрипт GPO. Один запуск от SYSTEM **не заменяет** обработку MAPI-профилей всех пользователей. Если в текущем сеансе открыт Outlook или MFCMAPI, исправление откладывается. При нескольких сеансах одного пользователя нужны дополнительные проверки.

Входящий в комплект [Run-RDS-OutlookRepair.cmd](Run-RDS-OutlookRepair.cmd) автоматически выбирает **x64 PowerShell** через **Sysnative**, если нужно, и запускает исправление **только профиля по умолчанию** текущего пользователя. Параметр **-AllProfiles** в PowerShell-обёртке используй осознанно: он обрабатывает и тестовые копии.

## Резервное копирование и безопасность

Перед изменениями основной скрипт экспортирует ветку реестра текущего пользователя:

~~~text
HKCU\Software\Microsoft\Office\16.0\Outlook\Profiles
~~~

Резервные копии и журналы сохраняются по умолчанию в:

~~~text
%LOCALAPPDATA%\OutlookImapRepair\
~~~

- Сначала выполняй **диагностику**, затем тест на **одном ящике** и только потом массовое исправление.
- После исправления проверь открытие параметров OST, доступность сжатия и синхронизацию IMAP.
- Массовое исправление **не транзакционное**: при ошибке одного ящика успешные изменения других автоматически не откатываются.
- Экспорт .reg **не является полной резервной копией почты** и не гарантирует простой автоматический откат. При необходимости сохраняй данные отдельно.
- В копиях профилей могут содержаться конфиденциальные параметры почтовых аккаунтов. Ограничивай доступ, **удаляй персональные данные из логов** перед публикацией.
- Не изменяй профили во время работы Outlook и запускай только проверенный исходный код.

## Как работает

Скрипт использует **Extended MAPI** для поиска Outlook-профилей текущего пользователя и служб **INTERSTOR**, сверяет оба исходных значения, записывает корректные типизированные свойства через **SetProps / SaveChanges** и выполняет повторную проверку. Слепая замена текста внутри бинарных значений реестра **не используется**.

Проект независимый, **не связан с Microsoft и не поддерживается ею**.
